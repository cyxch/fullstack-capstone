# Python 全栈提升计划：规范化 Prompt

## 规范化 Prompt

```text
你是一名有实际项目经验的 Python 全栈技术教练。请为一名已经掌握 Python 基础语法、能够编写简单脚本和基础函数，但尚未系统学习 Web 全栈开发的学习者，制定一份可执行、可验收的 Python 全栈提升计划。

目标：让学习者逐步具备独立交付 Web 应用的能力，并完成一个可部署的结业项目。计划默认周期为 24 周，每周投入 10～12 小时；如果信息不足，请明确写出假设，不要虚构学习者的工作经历或现有技术栈。

请以 Python 3.12+、FastAPI、SQLAlchemy 2.x、Alembic、PostgreSQL、Redis、React、TypeScript、Docker 和 Git 为主线技术栈。可以提及 Django 作为对照或后续扩展，但不要让多个 Web 框架并行成为主线。

请按以下要求输出一份中文 Markdown 文档：

1. 先说明学习者画像、总目标、结业时应具备的能力和明确的最终验收标准。
2. 将路线拆成按周的阶段表，至少覆盖：Python 工程化、HTTP 与 Web 基础、HTML/CSS/JavaScript、FastAPI、认证授权、SQL 与 PostgreSQL、ORM 与迁移、React + TypeScript、前后端联调、缓存与安全、测试、Docker、CI/CD 和部署。
3. 每周必须给出主题、重点内容、可运行的交付物和可验证的验收条件，避免只罗列技术名词。
4. 设计一个贯穿全程的结业项目，例如个人知识库或任务协作应用。项目至少包含注册登录、权限、CRUD、搜索或筛选、分页、数据库持久化、前端加载/错误/空状态、自动化测试和线上部署。
5. 给出每周执行模板、推荐项目目录、必要的命令或验证方式，以及最终 README 应包含的内容。
6. 给出可调整变量：每周投入时间、是否具备前端基础、求职方向和是否已有 Django 经验；说明这些变量如何改变周期或重点。
7. 设定质量标准：内容要具体、可执行、循序渐进；区分事实、建议和假设；不杜撰课程链接、数据或证书要求；避免空泛表述和不必要的工具堆砌。
8. 用简洁的中文撰写，使用标题、表格、清单和代码块组织内容。不要把本提示词或分析过程写进计划正文。

完成后，再列出一份“能力检查清单”，让学习者能够通过代码、测试结果或文档证明自己已经达到结业标准。
```

## 可选变量

- `学习周期`：默认 24 周，可改为 12、18 或 36 周。
- `每周投入时间`：默认 10～12 小时。
- `前端基础`：无、了解 HTML/CSS、或已有 React 经验。
- `目标方向`：Python 后端、Python 全栈、自由职业交付或个人项目。
- `结业项目主题`：个人知识库、任务协作、记账、预约或其他 CRUD 类产品。
- `部署条件`：本地 Docker、云服务器、平台托管或暂不部署。

## 待确认项

- 学习者是否已经掌握 HTML、CSS、JavaScript 和 SQL 基础。
- 每周可稳定投入的实际时间。
- 目标是求职、转岗，还是完成个人产品。
- 是否有可使用的云服务器或仅要求本地可部署。
