# Python 全栈提升计划

> 面向已经具备 Python 基础语法和简单编程能力、希望逐步具备独立交付 Web 应用能力的学习者。
>
> 默认周期：24 周；每周投入 10～12 小时；主线技术栈：Python 3.12+、FastAPI、PostgreSQL、Redis、React、TypeScript、Docker。

## 一、目标与完成标准

### 总目标

在 24 周内完成一个可部署的全栈项目，能够独立完成需求拆解、数据库设计、后端 API、前端页面、测试、容器化部署和基础运维，并能解释关键技术取舍。

### 结业时应具备的能力

- 用类型标注、模块化设计、异常处理和日志编写可维护的 Python 代码。
- 使用 Git 进行分支开发、提交组织、代码审查和冲突处理。
- 使用 FastAPI 构建带认证、校验、分页、权限和 OpenAPI 文档的 REST API。
- 使用 PostgreSQL 完成关系建模、索引、事务、迁移和常见查询优化。
- 使用 React + TypeScript 完成响应式页面、表单、状态管理和接口错误处理。
- 编写单元测试、接口测试和关键用户流程测试，并在 CI 中自动运行。
- 使用 Docker Compose 启动本地环境，将应用部署到一台云服务器或同等托管平台。
- 阅读官方文档和错误信息，定位并修复常见的依赖、网络、数据库和部署问题。

### 最终验收

完成一个“个人知识库/任务协作”类应用（以下称“结业项目”），至少包含：

1. 用户注册、登录、退出和密码安全存储。
2. 用户、工作区、项目、内容条目的关系模型和权限边界。
3. 条目的创建、编辑、搜索、筛选、分页和软删除。
4. 前端登录态、加载态、空状态、错误态和表单校验。
5. PostgreSQL 持久化、Redis 缓存或限流中的至少一项。
6. 自动化测试、Docker Compose、本地一键启动说明和线上可访问地址。
7. README、架构图、接口文档、数据库设计说明和一份复盘记录。

## 二、学习约定

- 每周至少安排 4 次学习，每次 60～90 分钟；每周末保留一次复盘和补缺。
- 学习顺序遵循“先做最小版本，再补工程质量”，避免同时切换多个框架。
- 每个阶段必须产出可运行代码、短文档和可复现的验证命令。
- 遇到问题先阅读报错、官方文档和最小复现，再查搜索结果；不要直接复制无法解释的代码。
- 每周提交至少 3 次 Git commit，提交信息说明实际变化。

| 15 | 前端状态与体验 | TanStack Query 或等效方案、缓存、加载/错误/空状态 | 页面刷新后登录态和数据状态行为明确，无明显重复请求 |
| 16 | TypeScript 深化 | 泛型、联合类型、API 类型、表单校验、组件边界 | 前端 API 类型与后端 Schema 对齐；消除主要 `any` |

| 18 | 全栈联调 | CORS、环境变量、统一错误、乐观更新、上传或搜索 | 前后端通过真实 API 完成一条端到端业务流程 |

| 20 | 领域功能 | 搜索、筛选、标签、权限、审计字段 | 结业项目达到 MVP；录制或截图展示核心流程 |
| 21 | 测试策略 | 单元、集成、API、前端组件、关键流程测试 | 后端核心逻辑和关键 API 有测试；失败时能定位模块 |
| 22 | 可观测性与重构 | 结构化日志、健康检查、配置分层、代码审查 | 修复一轮技术债；补充日志、错误追踪和架构说明 |

## 四、每周详细任务

下面每周按 10～12 小时拆分：前 2 小时学习和阅读，6～8 小时编码，最后 2 小时测试、整理和复盘。若当周任务没有通过验收，不要急着进入下一周，先保留一个最小可运行版本。

### 第 1 周：基线与开发工具

- 学习：安装 Python 3.12+、`uv`、Git、VS Code 和 PostgreSQL 客户端；了解解释器、虚拟环境、依赖锁定和 Git 工作区。
- 编码：创建仓库和 `hello-python` 包，编写环境检查脚本，输出 Python 版本、操作系统和依赖版本。
- 实践：创建 `.gitignore`、`README.md` 和 `pyproject.toml`；配置 `ruff`、`pytest` 和一个最小 CI 工作流。
- 验证：新建虚拟环境后能安装依赖；执行 `uv run pytest`、`uv run ruff check .` 和 `git diff --check` 均通过。
- 产出：环境检查脚本、项目初始化提交、`notes/weekly-01.md`。

### 第 2 周：Python 工程基础

- 学习：函数职责、模块导入、包结构、异常层次、上下文管理器、文件读写和 JSON 序列化。
- 编码：实现一个命令行任务清单，支持新增、完成、删除、查询，并将数据保存为 JSON。
- 重构：把命令行解析、业务逻辑和文件存储拆成独立模块；为文件不存在、格式错误和重复任务设计异常处理。
- 测试：为新增、完成、删除、空文件和非法 JSON 编写至少 5 个测试。
- 产出：可运行 CLI、测试报告、模块职责说明；验收时能解释每个模块为什么存在。

### 第 3 周：类型与代码质量

- 学习：类型注解、`Optional`、泛型、数据类、Pydantic 模型、日志级别和结构化错误信息。
- 编码：为第 2 周任务清单加入输入模型、返回类型和日志；把配置移到环境变量或配置对象。
- 工程化：配置 `ruff format`、Lint、测试覆盖率命令和 pre-commit 检查。
- 测试：补充边界输入测试，并让测试失败信息能定位到具体模块和场景。
- 产出：类型清晰的 CLI、质量检查命令和一份“错误处理约定”；验收时主要业务模块无无意义的 `Any`。

### 第 4 周：Web 与 HTTP 基础

- 学习：请求/响应、方法、状态码、Headers、Cookie、CORS、JSON、REST 资源命名和幂等性。
- 编码：用 Python Web 框架或标准库实现一个内存版任务 API，支持列表、详情、创建、更新和删除。
- 实践：用 curl 或接口工具发送正常请求、缺少字段、资源不存在和重复请求，记录返回结果。
- 测试：为至少 4 个状态码场景写接口测试，明确 2xx、4xx、5xx 的使用边界。
- 产出：API 示例请求文件、接口表和 HTTP 学习笔记；验收时能解释一次请求的完整生命周期。

### 第 5 周：HTML、CSS 与 JavaScript

- 学习：语义化 HTML、盒模型、Flex/Grid、响应式断点、DOM、事件、Promise、`fetch` 和浏览器调试工具。
- 编码：制作结业项目的静态首页和任务列表原型，支持新增任务、筛选任务和空状态显示。
- 实践：使用原生 `fetch` 调用一个公开 API，处理加载中、请求失败和返回数据为空的情况。
- 测试：在桌面和手机宽度检查布局；用浏览器 Network 面板确认请求、状态码和响应内容。
- 产出：响应式静态页面、页面截图和交互说明；验收时无横向滚动，键盘可完成主要操作。

### 第 6 周：TypeScript 与 React 入门

- 学习：TypeScript 基础类型、接口、联合类型、Props、State、Effect、组件拆分和基本路由。
- 编码：使用 Vite 创建 React + TypeScript 项目，将第 5 周页面改造成组件化任务列表。
- 实践：拆分 `TaskForm`、`TaskList`、`TaskItem` 和 `EmptyState`；为任务、筛选条件和表单事件定义类型。
- 测试：验证新增、完成、删除、过滤和无数据五条用户路径；修复浏览器控制台警告。
- 产出：React 任务列表、组件目录和启动说明；验收时能说明 State 应放在哪个组件以及原因。

### 第 7 周：FastAPI 基础

- 学习：FastAPI 路由、依赖注入、Pydantic Schema、OpenAPI、配置和应用生命周期。
- 编码：创建结业项目后端骨架，加入 `/health`、`/api/v1/items` 和统一配置模块。
- 实践：为创建、读取、更新、删除定义请求/响应 Schema；为字段长度、必填项和默认值添加校验。
- 测试：使用 TestClient 验证健康检查、合法请求和非法请求；访问 `/docs` 检查接口描述。
- 产出：后端可启动骨架、OpenAPI 文档截图、配置示例文件；验收时能从空目录启动服务。

### 第 8 周：API 设计与 CRUD

- 学习：分层结构、Service 与 Repository 职责、统一错误格式、分页、过滤和排序参数。
- 编码：完成条目 CRUD，至少支持 `page`、`page_size`、关键词搜索和按更新时间排序。
- 实践：把业务规则放入 Service 层，不在路由中堆叠数据库或业务逻辑；为资源不存在定义统一错误。
- 测试：覆盖成功、参数错误、资源不存在、重复操作和分页边界；保存一组可重复执行的接口请求。
- 产出：CRUD API、接口文档和错误码表；验收时前端或 curl 能完整走通一条 CRUD 流程。

### 第 9 周：认证与授权

- 学习：密码哈希、JWT 或会话、认证与授权的区别、依赖注入和资源所有权。
- 编码：实现注册、登录、当前用户和退出流程；密码只保存哈希，不记录明文。
- 实践：给条目接口增加“只能访问自己的资源”规则；区分未登录、无权限和资源不存在。
- 测试：覆盖重复邮箱、错误密码、过期令牌、跨用户访问和无令牌请求。
- 产出：认证模块、权限矩阵和安全配置说明；验收时能用测试证明用户 A 无法读写用户 B 的数据。

### 第 10 周：异步与后台任务

- 学习：`async`/`await`、异步 HTTP 客户端、超时、重试、取消和 FastAPI 后台任务边界。
- 编码：加入一个外部服务集成或异步导出任务，例如发送通知、生成内容摘要或导出 CSV。
- 实践：为外部调用设置连接和读取超时；对可重试错误最多重试 2～3 次，并记录上下文日志。
- 测试：使用 Mock 测试成功、超时、连续失败和重复触发；确认后台任务失败不会静默丢失。
- 产出：异步服务模块、失败处理说明和测试；验收时能解释哪些任务适合后台执行。

### 第 11 周：SQL 基础与数据库设计

- 学习：表、主键、外键、唯一约束、JOIN、聚合、事务、NULL 和范式基础。
- 编码：为用户、工作区、项目和内容条目设计 ER 图、字段表和关系基数。
- 实践：创建练习数据库，手写至少 10 条查询，包括列表、统计、关联、筛选和分页。
- 测试：准备重复数据、空关联和删除关联等边界数据，观察约束和事务行为。
- 产出：ER 图、建表 SQL、查询练习文件和数据字典；验收时能解释每个外键和关键约束。

### 第 12 周：SQLAlchemy 与 Alembic

- 学习：SQLAlchemy 2.x 模型、Session 生命周期、Repository、事务提交和 Alembic 迁移。
- 编码：将第 8～10 周 API 从内存存储迁移到 PostgreSQL；加入初始迁移和种子数据脚本。
- 实践：区分请求 Schema、数据库 Model 和响应 Schema；避免在请求结束后继续使用失效 Session。
- 测试：从空数据库执行迁移、插入种子数据、运行 API 测试，再回滚或重建数据库。
- 产出：PostgreSQL 版本 API、迁移文件和数据库启动说明；验收时新环境能从零创建数据库。

### 第 13 周：数据可靠性与查询优化

- 学习：索引原理、组合索引、事务边界、软删除、游标/偏移分页和 N+1 查询。
- 编码：为高频字段增加索引，加入 `created_at`、`updated_at`、软删除字段和数据唯一性约束。
- 实践：用 `EXPLAIN` 对比优化前后查询；检查列表接口是否重复查询关联数据。
- 测试：模拟并发更新、重复提交和删除后查询，确认数据状态符合预期。
- 产出：查询优化记录、索引迁移和可靠性测试；验收时能解释索引选择而不是只“加索引”。

### 第 14 周：React 工程化

- 学习：路由、受控表单、表单校验、可复用 Hook、请求封装和组件边界。
- 编码：完成登录、条目列表、条目详情和编辑四个页面，并配置受保护路由。
- 实践：建立 `lib/api` 请求层，统一处理 Base URL、认证 Header 和错误响应；拆分领域组件。
- 测试：验证直接访问受保护页面、返回上一页、编辑取消和保存失败等场景。
- 产出：四个核心页面、路由图和请求封装；验收时页面组件不直接拼接重复请求逻辑。

### 第 15 周：前端状态与请求体验

- 学习：服务端状态与本地 UI 状态的区别、缓存、失效、加载状态、错误状态和乐观更新。
- 编码：接入 TanStack Query 或等效方案，完成列表查询、详情查询、创建、更新和删除后的缓存处理。
- 实践：为页面补充骨架屏、空状态、重试按钮、保存中禁用和成功反馈。
- 测试：刷新页面、重复进入详情、网络失败和快速连续点击，确认不会出现明显重复请求或脏数据。
- 产出：状态管理方案、页面状态清单和演示截图；验收时每个请求状态都有可见反馈。

### 第 16 周：TypeScript 深化与类型对齐

- 学习：泛型、类型守卫、联合类型、API 响应类型、表单类型和组件公共接口。
- 编码：为 API 客户端、分页结果、错误响应和表单数据建立类型；消除主要业务路径中的 `any`。
- 实践：让后端 Schema 示例与前端类型保持一致，明确日期、空值和枚举的传输格式。
- 测试：执行 TypeScript 类型检查和生产构建；人为修改接口字段，确认编译阶段能发现不一致。
- 产出：类型目录、API 类型说明和构建记录；验收时接口变更不会悄悄变成运行时错误。

### 第 17 周：响应式与可访问性

- 学习：移动优先布局、语义标签、表单 Label、焦点管理、键盘操作和基本颜色对比。
- 编码：适配手机、平板和桌面布局；为弹窗、导航、表单和表格增加可访问结构。
- 实践：用键盘完成登录、搜索、编辑和删除；为按钮、输入框和错误信息补充明确文本。
- 测试：使用浏览器响应式模式和 Lighthouse 或等效工具检查布局、可读性和可操作性。
- 产出：响应式页面截图、可访问性检查记录；验收时核心流程不依赖鼠标且无内容遮挡。

### 第 18 周：全栈联调

- 学习：CORS、环境变量、前后端错误契约、上传/搜索流程和乐观更新的失败回滚。
- 编码：前端切换到真实 FastAPI API，完成“登录→创建条目→搜索→编辑→删除”的完整流程。
- 实践：区分开发、测试和生产配置；不把密钥、数据库密码和内部地址提交到 Git。
- 测试：在后端异常、网络断开、令牌过期和重复提交时观察前端行为并修复。
- 产出：真实 API 联调版本、环境变量模板和端到端流程截图；验收时不依赖 Mock 数据即可完成主流程。

### 第 19 周：缓存与安全

- 学习：Redis 基本数据结构、缓存过期、限流、XSS、SQL 注入、CSRF、密钥管理和依赖升级。
- 编码：为一个读多写少接口增加缓存，或为登录/搜索接口增加限流；设计缓存失效策略。
- 实践：检查 SQL 是否使用参数绑定；对用户输入、富文本和文件名进行约束；轮换开发密钥。
- 测试：验证缓存命中、数据更新后失效、超出限流和恶意输入等场景。
- 产出：安全检查清单、缓存或限流实现和风险说明；验收时能说清楚保护对象与剩余风险。

### 第 20 周：领域功能与 MVP

- 学习：需求拆分、用户故事、权限矩阵、搜索策略、标签模型和审计字段。
- 编码：完成搜索、筛选、标签、工作区权限和关键操作审计中的至少三项。
- 实践：写出 MVP 范围和明确不做的功能；删除不影响主流程的装饰性需求。
- 测试：按用户故事逐条验收，从新用户视角走完核心流程并记录阻塞点。
- 产出：可演示 MVP、功能清单、权限矩阵和演示脚本；验收时核心流程无需开发者手动改数据库。

### 第 21 周：测试体系

- 学习：测试金字塔、单元测试、集成测试、API 测试、前端组件测试和端到端测试。
- 编码：为 Service、认证、核心 CRUD、权限和搜索补齐测试；前端覆盖登录和创建条目流程。
- 实践：使用独立测试数据库和固定测试数据；避免测试依赖执行顺序或真实第三方服务。
- 验证：故意引入一个错误，确认测试能失败；修复后记录测试覆盖的行为而不只记录百分比。
- 产出：测试矩阵、自动化测试套件和失败定位说明；验收时核心路径测试可在一条命令中运行。

### 第 22 周：可观测性与重构

- 学习：结构化日志、请求 ID、健康检查、配置分层、错误分类和代码审查。
- 编码：增加访问日志、异常日志、数据库/缓存连接检查和基础指标；重构重复的业务逻辑。
- 实践：从一次失败请求的日志中定位用户、路径、参数摘要和异常位置；清理无用依赖和死代码。
- 测试：进行一次自我代码审查，检查命名、边界、错误处理、权限和测试缺口。
- 产出：重构前后说明、日志示例、架构图和技术债列表；验收时能用日志复现一次失败流程。

### 第 23 周：Docker 与 CI

- 学习：镜像、容器、网络、Volume、Dockerfile、Compose、健康检查和 CI 流程。
- 编码：分别为后端和前端构建镜像，用 Compose 启动应用、PostgreSQL 和 Redis；加入数据库初始化。
- 实践：为 CI 配置依赖安装、Lint、类型检查、后端测试和前端构建；缓存依赖但不缓存易过期数据。
- 测试：在没有本地依赖的干净环境执行启动命令；模拟 CI 失败并定位日志。
- 产出：`Dockerfile`、`docker-compose.yml`、CI 配置和一键启动说明；验收时新机器可按 README 启动。

### 第 24 周：部署、发布与复盘

- 学习：Linux 服务、反向代理、HTTPS、环境变量、数据库备份、监控、发布和回滚。
- 编码：部署到云服务器或同等平台，配置域名/HTTPS（条件允许时）、健康检查和最小监控。
- 实践：执行一次备份和恢复演练；发布一个小改动，再按文档回滚到上一版本。
- 整理：完成 README、架构图、ER 图、接口说明、测试范围、已知限制、演示地址和复盘文章。
- 产出：线上可访问项目、部署记录和 2～3 页复盘；验收时他人能仅凭 README 完成本地启动和功能验证。

## 五、每周执行模板

每周按以下顺序执行，并把结果写入项目仓库的 `notes/weekly-XX.md`：

1. **输入**：阅读官方文档一个主题，记录 3 个关键概念和 1 个不理解的问题。
2. **实现**：先写最小可运行版本，再补类型、错误处理和测试。
3. **验证**：执行格式化、Lint、测试和手工验收；保存关键命令与结果。
4. **复盘**：记录本周新增能力、一个踩坑、一个待改进点和下周任务。

每次编码结束前至少运行：

```bash
uv run ruff check .
uv run pytest
git diff --check
```

前端项目另外运行：

```bash
npm run lint
npm run build
```

## 七、资源与选型边界

- Python：优先阅读 Python 官方教程和标准库文档；不要同时学习多个异步 Web 框架。
- 后端：主线使用 FastAPI + SQLAlchemy 2.x + Alembic；完成主线后再用 Django 做一个小型对照项目。
- 前端：主线使用 React + TypeScript + Vite；先掌握浏览器和 JavaScript 基础，再引入状态库。
- 数据库：主线使用 PostgreSQL；SQLite 仅用于早期实验或测试，不作为线上数据库。
- 部署：优先 Docker Compose + 一台 Linux 云服务器；先完成可重复部署，再研究 Kubernetes。
- 第三方服务、云厂商和 UI 组件库可替换，但必须记录替换原因和等效验证方式。

## 八、能力检查清单

完成计划后，逐项回答并用代码或文档证明：

- 我能解释一次 HTTP 请求从浏览器到数据库再返回的完整路径。
- 我能说明认证、授权、密码哈希和密钥配置的区别。
- 我能定位一个慢查询，并说明索引是否真正生效。
- 我能为一个新接口补齐 Schema、权限、错误处理和测试。
- 我能解释 React 中状态、Effect、缓存和组件边界的取舍。
- 我能在新机器上启动项目，并在 CI 失败后定位问题。
- 我能说明线上数据库备份、日志、健康检查和回滚的基本方案。

若其中任一项只能“照着做”而不能解释，应回到对应周次补一个最小实验，并把实验结论写入复盘记录。

## 九、可调整变量

- `每周投入时间`：6～8 小时则将周期延长到 32～36 周；15 小时以上可将第 21～24 周拆成两个并行迭代。
- `前端基础`：完全没有 JavaScript 基础时，在第 5～6 周前增加 2 周 DOM、异步和 TypeScript 练习。
- `求职方向`：后端岗位可把第 14～17 周压缩为 3 周，把时间投入数据库、并发、系统设计和面试题；全栈岗位保留完整前端阶段。
- `已有 Django 经验`：可将第 7～10 周的一半替换为 Django + DRF，对比两种框架的路由、ORM、认证和部署方式。
